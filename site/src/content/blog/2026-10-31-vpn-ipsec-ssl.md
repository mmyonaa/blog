## 정의

VPN(Virtual Private Network)은 공중망(인터넷) 위에 암호화된 터널을 만들어 전용선처럼 쓰는 기술이다. 핵심 목표는 기밀성, 무결성, 송신자 인증이다. 정보보안기사에서는 VPN을 구현하는 대표 방식인 IPSec과 SSL(TLS) 기반 VPN을 비교하는 문제가 반복해서 나온다.

## IPSec VPN: 네트워크 계층(L3)에서 보호

IPSec은 IP 패킷 자체를 보호한다. 애플리케이션을 수정하지 않아도 그 위의 모든 프로토콜(TCP, UDP, ICMP)이 보호 대상이 된다. 구성 요소는 세 가지다.

| 구성 요소 | 역할 |
|---|---|
| AH (Authentication Header) | 무결성, 데이터 출처 인증, 재전송 방지. 암호화는 하지 않는다 |
| ESP (Encapsulating Security Payload) | 기밀성(암호화) + 선택적으로 무결성·인증 |
| IKE (Internet Key Exchange) | SA(Security Association) 협상과 키 교환 |

- SA는 단방향 논리적 약속(알고리즘, 키, 수명)이며 SPI라는 식별자로 구분한다. 양방향 통신에는 SA가 두 개 필요하다.
- AH는 IP 프로토콜 번호 51, ESP는 50을 쓴다. IKE는 UDP 500을 사용한다.
- AH는 IP 헤더까지 무결성 검사 범위에 포함하기 때문에, 주소를 바꾸는 NAT를 통과하면 검증이 깨진다. 그래서 NAT 환경에서는 ESP를 UDP로 캡슐화하는 NAT-T(UDP 4500)를 쓰는 것이 일반적이다.

### 전송 모드와 터널 모드

```text
전송(Transport) 모드: [원본 IP 헤더][IPSec 헤더][페이로드]
터널(Tunnel) 모드:    [새 IP 헤더][IPSec 헤더][원본 IP 헤더][페이로드]
```

전송 모드는 호스트 간 통신에서 페이로드만 보호한다. 터널 모드는 원본 패킷 전체를 감싸 새 IP 헤더를 붙이므로 내부 주소가 숨겨진다. 보안 게이트웨이 간 사이트 대 사이트 VPN은 터널 모드가 기본이다.

## SSL VPN: 전송 계층 위(TLS)에서 보호

SSL VPN은 TLS 위에서 동작한다. 보통 TCP 443을 쓰기 때문에 방화벽을 통과하기 쉽고, 웹 브라우저만으로 접속하는 클라이언트리스 방식도 가능하다. 사용자가 접근할 수 있는 자원을 애플리케이션 단위로 세밀하게 제한하기 좋아 원격 근무자나 외부 협력사 접속에 많이 쓰인다. 제품에 따라 별도 에이전트를 설치해 IP 수준의 터널을 제공하는 방식도 있다.

## 비교

| 항목 | IPSec VPN | SSL VPN |
|---|---|---|
| 동작 계층 | 네트워크 계층 | 전송~응용 계층 |
| 주된 용도 | 사이트 간 연결, 전용 클라이언트 | 원격 사용자 접속 |
| 클라이언트 | 전용 소프트웨어 필요 | 브라우저 또는 경량 에이전트 |
| 보호 범위 | 모든 IP 트래픽 | 주로 애플리케이션 단위 |
| 방화벽·NAT | 설정이 까다로울 수 있음 | 443 사용으로 비교적 쉬움 |

## 시험에 자주 나오는 포인트

- AH는 암호화를 하지 않고, 기밀성이 필요하면 ESP를 쓴다.
- AH는 NAT와 충돌한다. NAT-T는 ESP를 UDP 4500으로 감싸 우회한다.
- IKE는 UDP 500이며 SA를 협상한다. SA는 단방향이라 양방향에는 두 개가 필요하다.
- 터널 모드는 원본 IP 헤더까지 보호하고, 전송 모드는 페이로드만 보호한다.
- SSL VPN은 클라이언트 설치 부담이 적고 443을 쓰며, IPSec은 계층이 낮아 애플리케이션에 투명하다.
