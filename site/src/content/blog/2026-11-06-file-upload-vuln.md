## 정의

파일 업로드 취약점은 서버가 사용자가 올린 파일의 종류와 저장 위치를 충분히 검증하지 않아, 공격자가 실행 가능한 스크립트를 서버에 올리고 실행할 수 있게 되는 결함이다. 이렇게 올라간 악성 스크립트를 **웹셸(WebShell)**이라 한다. 파일 다운로드 취약점은 반대로 다운로드할 파일 경로를 사용자 입력으로 받을 때, 의도하지 않은 서버 내부 파일을 내려받게 되는 결함이다.

## 업로드 공격의 원리

1. 게시판·프로필 사진 등 업로드 기능에 `shell.jsp`, `shell.php` 같은 스크립트를 올린다.
2. 파일이 웹 루트 아래 실행 가능한 경로에 저장되면, 공격자는 그 URL을 직접 호출한다.
3. 웹 서버가 파일을 정적 자원이 아니라 스크립트로 해석해 실행하고, 공격자는 명령 실행·파일 조회·DB 접근 권한을 얻는다.

핵심은 "올릴 수 있다"와 "실행된다"가 동시에 성립한다는 점이다. 둘 중 하나만 끊어도 피해는 크게 줄어든다.

### 흔한 우회 기법

| 방어 | 우회 예 |
|---|---|
| 클라이언트(자바스크립트) 검증 | 프록시로 요청을 가로채 변조 |
| Content-Type 헤더 검사 | 헤더 값을 `image/png`로 위조 |
| 확장자 블랙리스트 | 대소문자 혼용, 이중 확장자(`a.php.jpg`), 널 바이트 삽입 등 |
| 확장자만 검사 | 이미지 파일 끝에 스크립트를 덧붙인 파일 |

블랙리스트는 빠뜨린 확장자가 곧 구멍이 되므로 근본 대책이 못 된다.

## 다운로드 취약점: 경로 순회

다운로드 기능이 `download?file=report.pdf`처럼 파일명을 파라미터로 받는데 경로를 검증하지 않으면, `../../etc/passwd`처럼 상위 디렉터리를 가리키는 값으로 임의 파일을 읽을 수 있다. 이를 **경로 순회(Path Traversal, Directory Traversal)**라 한다. `%2e%2e%2f`처럼 URL 인코딩한 값으로 필터를 피하려는 시도도 흔하다.

## 대응 방안

- **화이트리스트 확장자 검증**: 허용할 확장자(jpg, png, pdf 등)만 명시하고 나머지는 거부한다. 검증은 반드시 서버에서 한다.
- **저장 파일명 변경**: 원본 파일명 대신 서버가 생성한 난수 이름으로 저장하고, 원본명은 DB에만 둔다.
- **저장 위치 분리**: 업로드 디렉터리를 웹 루트 밖에 두거나, 웹 루트 안이라면 해당 디렉터리의 스크립트 실행 권한을 제거한다.
- **파일 내용 검사**: 시그니처(매직 넘버) 확인, 이미지 재인코딩 등으로 위장 파일을 걸러낸다.
- **크기 제한과 백신 검사**: 대용량 업로드로 인한 자원 고갈을 막는다.
- **다운로드 시 경로 고정**: 사용자 입력을 경로가 아닌 파일 ID로 받아 서버가 매핑하고, 입력에서 `..`, `/`, `\` 등을 제거하거나 정규화 후 허용 디렉터리 안인지 확인한다.
- **서버 설정**: 웹 서버 프로세스를 최소 권한으로 실행해 침해 시 영향을 줄인다.

## 시험에 자주 나오는 포인트

- 웹셸의 정의와, 업로드 취약점의 결과가 원격 명령 실행으로 이어진다는 점.
- 클라이언트 측 검증만으로는 방어가 되지 않는다는 점, 블랙리스트보다 화이트리스트가 원칙이라는 점.
- 경로 순회 공격에 쓰이는 `../` 패턴과 대응(입력 검증, 경로 정규화, 파일 ID 매핑).
- 업로드 파일을 웹 루트 밖에 저장하거나 실행 권한을 제거하는 대책.
- 같은 입력 검증 부재에서 비롯된 SQL 인젝션과 함께, 입력값을 신뢰하지 않는다는 원칙으로 묶어 정리해 두면 서술형에 대응하기 좋다.
