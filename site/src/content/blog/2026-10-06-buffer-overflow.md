## 정의

버퍼 오버플로우는 프로그램이 버퍼에 할당된 크기보다 많은 데이터를 쓸 때, 인접한 메모리 영역이 덮어써지는 취약점이다. 메모리 영역에 따라 스택 오버플로우와 힙 오버플로우로 나누는데, 시험에서 가장 자주 다루는 것은 스택 쪽이다.

## 핵심 원리

함수가 호출되면 스택에는 지역 변수(버퍼), 저장된 베이스 포인터(SFP), 리턴 주소가 차례로 쌓인다. 스택은 높은 주소에서 낮은 주소로 자라지만, 버퍼에 데이터를 쓰는 방향은 낮은 주소에서 높은 주소다. 그래서 버퍼 길이를 넘겨 쓰면 SFP를 지나 리턴 주소까지 덮어쓸 수 있다.

```text
높은 주소
  [ 리턴 주소 ]   <- 공격자가 원하는 주소로 덮어쓰기
  [ SFP       ]
  [ buf[64]   ]   <- 여기서부터 길이 검사 없이 쓰기
낮은 주소
```

함수가 끝나고 `ret`이 실행되면 CPU는 덮어쓴 주소로 점프한다. 공격자가 그 주소를 직접 주입한 코드(쉘코드)나 기존 코드 조각으로 향하게 하면 임의 코드 실행이 가능해진다. 실행 권한이 SetUID가 걸린 프로그램이면 권한 상승으로 이어진다.

## 예시

아래는 전형적인 취약 코드다.

```c
#include <string.h>

void vuln(const char *input) {
    char buf[64];
    strcpy(buf, input);   /* 길이 검사 없음 */
}
```

`strcpy`는 입력 길이를 확인하지 않는다. 같은 부류의 함수로 `gets`, `sprintf`, `strcat`, `scanf("%s")` 등이 있고, 대체로 `strncpy`, `snprintf`, `fgets`처럼 길이를 지정하는 함수로 바꾼다. 다만 `strncpy`는 널 종료를 보장하지 않으므로 직접 처리해야 한다.

## 방어 기법

| 구분 | 방어 | 설명 |
|------|------|------|
| 코드 | 안전한 함수, 입력 길이 검증 | 근본 대책 |
| 컴파일러 | 스택 카나리(Stack Canary) | 리턴 주소 앞에 임의 값을 두고, 함수 종료 시 변조 여부를 검사 |
| OS | DEP/NX | 스택·힙 영역에서 코드 실행을 금지 |
| OS | ASLR | 스택·힙·라이브러리의 주소를 실행마다 무작위화 |

각 방어는 우회 기법이 존재한다. DEP를 피하려고 기존 코드 조각을 이어 붙이는 ROP(Return-Oriented Programming), 대표적으로 `system` 같은 라이브러리 함수로 흐름을 돌리는 Return-to-libc가 있다. ASLR은 주소 정보가 유출되면 힘을 잃는다. 그래서 방어는 하나만 쓰지 않고 겹겹이 적용한다.

## 시험에 자주 나오는 포인트

- 덮어쓰는 대상은 리턴 주소이며, 스택은 높은 주소에서 낮은 주소로 자란다는 점을 구분한다.
- 취약 함수 목록(`strcpy`, `strcat`, `gets`, `sprintf`)과 대응 안전 함수를 짝지어 외운다.
- 카나리는 컴파일러, DEP·ASLR은 OS 수준의 방어라는 층위를 구분한다.
- DEP를 우회하는 기법이 Return-to-libc와 ROP라는 연결을 기억한다.
- 힙 오버플로우는 힙의 메타데이터나 함수 포인터를 노리는 별도 유형이며, 스택 오버플로우와 구분해 출제된다.
