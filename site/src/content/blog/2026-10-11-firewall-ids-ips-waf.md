네 장비는 모두 "네트워크를 지키는 장비"로 묶이지만 무엇을 보고 무엇을 하느냐가 다르다. 구분 기준은 세 가지다: 어느 계층을 보는가, 탐지만 하는가 차단까지 하는가, 어디에 놓이는가.

## 방화벽: 접근 통제

방화벽은 정해진 정책(출발지·목적지 IP, 포트, 프로토콜)에 따라 트래픽을 허용하거나 거부한다. 기본은 3~4계층 정보를 보는 패킷 필터링이다.

- **상태 기반 검사(Stateful Inspection)**: 연결 상태 테이블을 유지해 이미 허용된 세션에 속한 응답 패킷만 통과시킨다. 단순 패킷 필터링보다 위조 패킷에 강하다.
- **애플리케이션 게이트웨이(프록시)**: 7계층까지 보고 클라이언트와 서버 사이에서 연결을 중계한다. 내용 검사가 가능하지만 느리다.
- 정책의 기본 원칙은 "명시적으로 허용한 것 외에는 모두 거부"(화이트리스트)다.

방화벽은 허용된 포트(예: 80, 443) 안에 실린 공격 내용은 판단하지 못한다. 이 빈틈을 IDS·IPS·WAF가 메운다.

## IDS와 IPS: 침입 탐지와 방지

| 구분 | IDS | IPS |
|---|---|---|
| 역할 | 탐지, 경보 | 탐지 + 자동 차단 |
| 배치 | 미러링(SPAN/TAP) 방식, 경로 밖 | 인라인(트래픽 경로 위) |
| 오탐 영향 | 경보만 늘어남 | 정상 트래픽 차단 위험 |
| 장애 영향 | 서비스 무관 | 장애 시 통신 단절 가능 |

탐지 방식은 두 가지다.

- **오용(Misuse, 시그니처) 탐지**: 알려진 공격 패턴과 대조한다. 오탐이 적지만 새로운 공격은 놓친다.
- **이상(Anomaly) 탐지**: 정상 행위 기준선에서 벗어난 것을 잡는다. 새 공격도 탐지할 수 있지만 오탐이 많다.

설치 위치로는 네트워크 기반(NIDS/NIPS)과 호스트 기반(HIDS/HIPS)이 나뉜다. 호스트 기반은 암호화된 통신이 복호화된 뒤의 행위나 파일 변조도 볼 수 있다는 점이 강점이다.

## WAF: 웹 애플리케이션 방화벽

WAF는 HTTP/HTTPS 요청의 내용을 7계층에서 해석해 SQL 인젝션, XSS 같은 웹 공격 패턴을 막는다. 일반 방화벽이 포트를 본다면 WAF는 요청 URL, 파라미터, 헤더, 본문을 본다. HTTPS 트래픽을 검사하려면 WAF 지점에서 복호화가 필요하다. 배치는 리버스 프록시, 인라인 브리지, 서버 에이전트 등 여러 형태가 있다.

## 예시: 같은 요청, 다른 판단

공격자가 80번 포트로 `GET /board?id=1' OR '1'='1` 요청을 보낸다고 하자.

- 방화벽: 목적지가 웹서버의 80번 포트이므로 허용한다.
- IDS: SQL 인젝션 시그니처와 일치하면 경보를 남긴다. 요청은 이미 통과했다.
- IPS: 같은 시그니처로 해당 패킷을 차단한다.
- WAF: 웹 요청 문맥에서 공격으로 판단해 차단하고, 웹 로그에 남긴다.

## 시험 포인트

- 방화벽은 내용이 아니라 헤더 기반 정책 통제, 허용된 서비스 안의 공격은 막지 못한다.
- IDS는 탐지만, IPS는 인라인 차단. "오탐 시 서비스 장애" 가능성은 IPS 쪽 단점이다.
- 오용 탐지는 알려진 공격 위주로 오탐이 적고, 이상 탐지는 알려지지 않은 공격 탐지가 가능하지만 오탐이 많다.
- 웹 공격 방어는 WAF, 방화벽의 기본 정책은 default deny.
- 상태 기반 방화벽은 세션 테이블, 프록시 방화벽은 연결 중계라는 키워드로 구분한다.
