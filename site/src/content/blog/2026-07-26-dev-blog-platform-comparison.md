개발 블로그를 시작할 때 가장 먼저 부딪히는 결정은 글감이 아니라 플랫폼이다. 한국 개발자 기준으로 선택지는 크게 네 갈래로 좁혀진다 — velog, Tistory, Medium, 그리고 GitHub Pages 계열의 직접 구축. 넷은 기능 목록으로 비교하면 끝이 없지만, 사실 하나의 축으로 정리된다. **플랫폼이 독자를 데려다주는 대신 제어권을 가져가고, 직접 만들면 제어권을 갖는 대신 독자를 스스로 데려와야 한다.**

## velog — 개발자 독자가 이미 모여 있는 곳

velog는 한국 개발자 블로그의 사실상 기본값이 됐다. 마크다운 에디터, 목차 자동 생성, 시리즈·태그, 그리고 무엇보다 **트렌딩 피드와 팔로우로 굴러가는 개발자 생태계**가 강점이다. 글을 올리면 플랫폼이 독자를 데려온다 — 이게 velog가 공짜로 주는 가장 큰 자산이다. 도메인 자체의 검색 노출도 유리한 편이다.

약점은 그 대가다. 커스터마이징이 사실상 불가능해서 모든 velog 블로그가 똑같이 생겼고, 조회 통계는 부실하며, 광고·수익화 수단이 없다. 주소도 `velog.io/@아이디` 서브 경로로 고정된다. 글은 내 것이지만 **집은 내 것이 아니다.**

## Tistory — 커스터마이징과 수익화

Tistory는 스킨 편집으로 HTML·CSS 수준의 커스터마이징이 되고, 자체 방문 통계와 광고 수익화가 가능하다. "내 마음대로 꾸미고 광고도 붙이고 싶은데, 서버까지 직접 만들긴 싫다"는 지점에 정확히 맞는다.

대신 개발자 커뮤니티로서의 밀도는 velog보다 낮고, 카카오 계정과 정책에 종속된다. 플랫폼 정책이 바뀌면 따라가는 수밖에 없다는 점은 오래 운영할수록 무시하기 어려운 리스크다.

## Medium — 넓은 독자, 그러나 한글엔 불리

Medium은 에디터와 읽기 경험이 매끄럽고, 개발자를 넘어선 넓은 영문 독자층과 파트너 프로그램(유료 구독 수익 배분)이 있다. 영어로 쓰고 글로벌 독자를 노린다면 유력한 선택지다.

다만 커스터마이징이 거의 없고, 무료 열람 제한(페이월)이 독자 경험을 해치며, 한글 콘텐츠와 코드 중심 글에는 검색 노출·편의 모두 상대적으로 불리하다. 한국어 기술 블로그 용도로는 우선순위가 밀린다.

## GitHub Pages — 전부 내 것, 전부 내 일

GitHub Pages(또는 Netlify·Vercel 등에 올리는 정적 사이트)는 코드·디자인·도메인·데이터까지 **완전한 소유와 제어**를 준다. 호스팅은 무료이고, git push가 곧 배포다. Astro·Hugo·Jekyll 같은 SSG를 얹으면 마크다운으로 쓰는 워크플로도 자연스럽다.

대가는 명확하다. 에디터·댓글·검색·통계·SEO 전부 직접 만들거나 붙여야 하고, 무엇보다 **독자가 0에서 시작한다.** 트렌딩 피드가 없으니 홍보하지 않으면 아무도 오지 않는다. 기술 진입장벽과 유지보수 비용도 온전히 내 몫이다.

## 한 장 요약

| | velog | Tistory | Medium | GitHub Pages |
|---|---|---|---|---|
| 커스터마이징 | ✖ | △ 스킨 | ✖ | ✅ 완전 |
| 독자 유입 | ✅ 트렌딩·피드 | △ | ✅ 영문권 | ✖ 0에서 시작 |
| 통계 | △ | ✅ | △ | 직접 연결 |
| 수익화 | ✖ | ✅ 광고 | △ 파트너 | 직접 구성 |
| 유지보수 | 없음 | 없음 | 없음 | **전부 내 몫** |
| 소유권 | 글만 | 글만 | 글만 | ✅ 전부 |

## 그래서 무엇을 고를까

- **글이 읽히는 경험이 우선**이고 당장 쓰기 시작하고 싶다면 → velog. 개발자 독자를 플랫폼이 데려온다.
- **꾸미기와 광고 수익**이 목적이라면 → Tistory.
- **영어로 넓은 독자**를 노린다면 → Medium.
- **웹 기술을 배우면서 완전한 소유권**을 갖고 싶다면 → 정적 사이트 직접 구축.

중요한 건 이 선택이 우열이 아니라 트레이드오프라는 점이다. 플랫폼 블로그는 distribution(독자 유입)을 주고 product(사이트 자체)의 제어를 가져간다. 직접 만들면 그 반대다. 자신이 블로그에서 최적화하고 싶은 것이 무엇인지 — 읽힐 확률인지, 만드는 경험과 소유인지 — 를 먼저 정하면 답은 거의 자동으로 나온다.
