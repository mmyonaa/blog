블랙박스·화이트박스가 "어떻게 테스트 케이스를 만드나"의 분류라면, 테스트 레벨은 "개발의 어느 단계에서 무엇을 대상으로 테스트하나"의 분류다. 정보처리기사에서는 네 레벨의 순서와 각 레벨이 대응하는 개발 단계, 그리고 통합 테스트의 방식별 특징과 스텁·드라이버 구분이 반복해서 출제된다.

## 테스트 레벨 네 가지

V-모델은 개발 단계와 테스트 단계를 좌우 대칭으로 놓는다. 왼쪽 단계에서 만든 산출물이 오른쪽 테스트의 기준이 된다.

| 테스트 레벨 | 대상 | 대응 개발 단계 | 주로 하는 사람 |
| --- | --- | --- | --- |
| 단위 테스트 | 모듈(함수·클래스) 하나 | 구현(코딩) | 개발자 |
| 통합 테스트 | 모듈 사이의 인터페이스 | 상세 설계 | 개발자·테스터 |
| 시스템 테스트 | 통합된 시스템 전체 | 기본 설계 | 테스터 |
| 인수 테스트 | 사용자 요구사항 충족 여부 | 요구사항 분석 | 사용자·고객 |

- **단위 테스트**는 모듈 내부 로직을 보므로 화이트박스 기법을 주로 쓴다.
- **통합 테스트**는 모듈끼리 붙였을 때 인터페이스 불일치, 데이터 전달 오류를 찾는다.
- **시스템 테스트**는 기능 요구사항뿐 아니라 성능·보안·회복 같은 비기능 요구사항까지 확인한다.
- **인수 테스트**는 알파 테스트와 베타 테스트로 나뉜다. 알파는 개발자 환경에서 사용자가 개발자 입회하에 수행하고, 베타는 사용자 환경에서 사용자가 직접 수행한다.

## 통합 테스트 방식

모듈을 어떤 순서로 붙여 가며 테스트하느냐에 따라 나뉜다.

**빅뱅 통합**은 모듈을 전부 만든 뒤 한꺼번에 결합해 테스트한다. 준비가 단순하지만 오류가 나면 어느 모듈 사이의 문제인지 찾기 어렵다. 규모가 작을 때만 쓴다.

**점증적 통합**은 모듈을 하나씩 더해 가며 테스트한다. 오류 위치를 좁히기 쉽고, 아직 없는 모듈은 대역으로 채운다. 방향에 따라 세 가지다.

- **하향식**: 최상위 모듈부터 아래로 내려간다. 깊이 우선 또는 너비 우선으로 하위 모듈을 붙인다. 아직 없는 하위 모듈 자리에 **스텁**을 둔다. 제어 구조와 주요 설계 결함을 일찍 확인할 수 있지만, 스텁을 많이 만들어야 하고 하위 모듈의 검증이 늦어진다.
- **상향식**: 최하위 모듈부터 위로 올라간다. 관련 하위 모듈을 **클러스터**로 묶고, 아직 없는 상위 모듈 자리에 **드라이버**를 둔다. 스텁이 필요 없고 하위 모듈을 철저히 검증하지만, 시스템 전체 골격은 마지막에야 보인다.
- **샌드위치(혼합식)**: 상위는 하향식, 하위는 상향식으로 동시에 진행한다. 두 방식의 장점을 취하지만 비용이 크다.

## 스텁과 드라이버

둘 다 "아직 없는 모듈을 대신하는 가짜"지만 방향이 반대다.

| 구분 | 스텁(Stub) | 드라이버(Driver) |
| --- | --- | --- |
| 대신하는 것 | 하위(호출되는) 모듈 | 상위(호출하는) 모듈 |
| 쓰이는 방식 | 하향식 | 상향식 |
| 하는 일 | 호출받으면 정해진 값을 돌려준다 | 테스트 대상을 호출하고 결과를 받는다 |

주문 처리 모듈을 하향식으로 테스트하는데 결제 모듈이 아직 없다면, 결제 스텁은 이렇게 생긴다.

```python
def pay(order_id, amount):
    # 결제 모듈 스텁: 실제 결제 없이 성공만 돌려준다
    return {"ok": True, "tx": "STUB-0001"}
```

반대로 결제 모듈만 먼저 완성됐고 그걸 호출할 주문 모듈이 없다면, 드라이버가 결제 모듈을 직접 불러 본다.

```python
def driver():
    result = pay("order-1", 12000)
    assert result["ok"] is True
```

## 회귀 테스트

레벨과 별개로, 모듈을 수정하거나 새 모듈을 통합한 뒤 **이미 통과했던 테스트를 다시 돌리는 것**을 회귀 테스트라 한다. 통합 테스트 과정에서 모듈이 하나 추가될 때마다 기존 테스트가 깨지지 않았는지 확인하는 용도로 함께 출제된다.

## 시험에 자주 나오는 포인트

- 하향식 통합에 필요한 대역은 **스텁**, 상향식에 필요한 대역은 **드라이버**. 이 짝을 바꿔 내는 보기가 단골이다.
- 상향식의 "클러스터"는 하위 모듈 묶음이지, 서버 클러스터가 아니다.
- V-모델 대응: 단위↔구현, 통합↔상세 설계, 시스템↔기본 설계, 인수↔요구사항 분석.
- 알파는 개발자 환경, 베타는 사용자 환경. 장소로 구분한다.
- 빅뱅의 단점은 "오류 원인 추적이 어렵다". 장점을 묻는 문제는 거의 없다.
- 샌드위치는 하향식과 상향식의 혼합이며, 통합 방식이지 테스트 기법 분류가 아니다.
