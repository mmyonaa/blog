## 인증이란

인증(Authentication)은 접근을 요청한 주체가 주장하는 신원이 맞는지 확인하는 절차다. 신원을 밝히는 식별(Identification), 확인하는 인증, 확인된 주체에게 권한을 부여하는 인가(Authorization)는 구분해서 외워 둔다. 인증의 강도는 어떤 증거를 요구하느냐로 갈린다.

## 인증의 3요소

| 요소 | 의미 | 예 |
|---|---|---|
| 지식 기반 | 사용자가 아는 것 | 패스워드, PIN, 질문 답변 |
| 소유 기반 | 사용자가 가진 것 | OTP 토큰, 스마트카드, 인증서 |
| 존재(특성) 기반 | 사용자 그 자체 | 지문, 홍채, 얼굴, 정맥 |

서로 다른 요소를 둘 이상 결합하면 다중 요소 인증(MFA)이다. 패스워드와 보안 질문처럼 같은 요소(지식)만 두 번 쓰는 것은 다중 요소가 아니다. 시험에서 자주 걸리는 함정이다.

## OTP: 한 번만 쓰는 패스워드

OTP(One-Time Password)는 사용할 때마다 값이 바뀌므로, 값이 노출되거나 재전송(replay)되어도 다음 인증에 쓸 수 없다. 생성 방식은 크게 셋이다.

- **시간 동기화(TOTP)**: 토큰과 서버가 같은 비밀키와 현재 시각으로 값을 계산한다. 일정 시간(흔히 30초 안팎)마다 값이 바뀌며 시계가 어긋나면 인증이 실패한다. 표준은 RFC 6238이다.
- **이벤트(카운터) 동기화(HOTP)**: 시간 대신 사용 횟수 카운터를 입력으로 쓴다. 버튼을 누를 때마다 카운터가 증가하며, 서버와 카운터가 어긋나면 허용 범위 안에서 재동기화한다. 표준은 RFC 4226이다.
- **챌린지-응답**: 서버가 보낸 임의의 난수(challenge)를 토큰에 입력하면, 토큰이 비밀키로 계산한 응답값을 돌려준다. 동기화 문제가 없지만 사용자가 값을 한 번 더 입력해야 한다.

세 방식 모두 핵심은 비밀키를 공유한 상태에서 서버와 토큰이 같은 값을 독립적으로 계산한다는 점이다. 비밀키 자체는 네트워크에 오가지 않는다.

한계도 있다. OTP를 가로채 즉시 위조 사이트에 입력하는 실시간 피싱(중간자 공격)에는 약하다. 값이 유효한 시간 안에는 공격자도 쓸 수 있기 때문이다.

## 생체인증

생체인증은 분실·망각 위험이 낮지만, 유출되면 패스워드처럼 바꿀 수 없다는 약점이 있다. 평가 지표는 다음과 같다.

- **FRR(False Rejection Rate, 오인식률)**: 정당한 사용자를 거부하는 비율. 높으면 불편하다.
- **FAR(False Acceptance Rate, 오수락률)**: 타인을 정당한 사용자로 받아들이는 비율. 높으면 보안이 뚫린다.
- **EER(Equal Error Rate)**: FAR와 FRR이 같아지는 지점의 오류율. 낮을수록 정확한 장치다.

임계값(threshold)을 엄격하게 잡으면 FAR는 낮아지고 FRR는 높아지며, 느슨하게 잡으면 반대가 된다. 두 값은 서로 상충한다. 보안이 중요한 시설은 FAR를 낮추는 쪽으로, 편의가 중요한 환경은 FRR를 낮추는 쪽으로 설정한다.

## 시험 포인트

- 같은 요소 두 개는 MFA가 아니다. 요소 분류(지식·소유·존재)를 문제 보기에서 바로 판별할 수 있어야 한다.
- OTP는 재전송 공격에 강하지만, 실시간 피싱에는 취약하다.
- TOTP는 시각, HOTP는 카운터, 챌린지-응답은 서버 난수가 입력이다.
- 생체인증은 FAR와 FRR가 반비례하며, 교차점이 EER이다.
- 생체 정보는 변경이 어려워 유출 시 피해가 크므로, 원본이 아닌 템플릿 형태로 보호해 저장해야 한다.
