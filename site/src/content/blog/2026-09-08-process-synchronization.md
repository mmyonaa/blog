여러 프로세스나 스레드가 같은 자원을 동시에 건드리면 결과가 실행 순서에 따라 달라지는 경쟁 상태(race condition)가 생긴다. 프로세스 동기화는 이 경쟁을 막기 위해 공유 자원에 대한 접근 순서를 통제하는 메커니즘이다.

## 임계구역

공유 자원을 참조하는 코드 영역을 임계구역(critical section)이라 부른다. 두 프로세스가 동시에 임계구역에 들어가면 값을 서로 덮어써 데이터가 깨질 수 있다. 임계구역 문제를 올바르게 해결하려면 세 조건을 모두 만족해야 한다.

- 상호 배제(mutual exclusion): 한 순간에 하나의 프로세스만 임계구역에 들어간다.
- 진행(progress): 임계구역이 비어 있으면, 들어가려는 프로세스 중 하나는 반드시 들어갈 수 있어야 한다.
- 한정 대기(bounded waiting): 한 프로세스가 임계구역에 들어가기까지 다른 프로세스의 새치기 횟수에 상한이 있어야 한다.

## 뮤텍스와 세마포어

뮤텍스(mutex)는 자물쇠 하나다. lock을 건 프로세스만 unlock할 수 있고, 값은 0/1(잠김/열림) 두 상태뿐이다. 소유권 개념이 있어 락을 건 스레드가 아니면 풀 수 없다.

세마포어(semaphore)는 정수 카운터다. P 연산(wait, 카운터를 감소시키고 0 미만이면 대기)과 V 연산(signal, 카운터를 증가시키고 대기 중인 프로세스를 깨움)으로 조작한다. 값을 0과 1로만 쓰면 이진 세마포어로 뮤텍스처럼 동작하지만, 소유권 검사가 없어 아무 프로세스나 V를 호출할 수 있다는 점이 다르다. 카운터를 2 이상으로 두면 동시 접근 가능한 자원 개수를 제한하는 카운팅 세마포어가 된다 — DB 커넥션 풀처럼 "동시에 N개까지만" 상황에 쓴다.

## 예시: 생산자-소비자 문제

버퍼 하나를 여러 생산자와 소비자가 공유하는 고전 문제는 세마포어 세 개로 푼다.

```
empty = N   // 빈 슬롯 수
full = 0    // 채워진 슬롯 수
mutex = 1   // 버퍼 접근용 이진 세마포어

producer():
    P(empty); P(mutex)
    버퍼에 항목 추가
    V(mutex); V(full)

consumer():
    P(full); P(mutex)
    버퍼에서 항목 제거
    V(mutex); V(empty)
```

empty와 full은 버퍼가 가득 찼거나 비었을 때 상대편을 대기시키고, mutex는 버퍼 조작이 겹치지 않게 막는다. P(mutex)를 P(empty)보다 먼저 걸면 생산자가 mutex를 쥔 채 대기해 소비자도 진입 못 하는 상태가 생기므로 두 P 연산의 순서가 중요하다.

## 시험에 자주 나오는 포인트

- 임계구역 3원칙(상호 배제·진행·한정 대기)의 이름과 정의를 구분해서 묻는다.
- 뮤텍스와 이진 세마포어를 같은 것으로 헷갈리기 쉽다. 소유권 유무가 핵심 차이다.
- 세마포어의 P는 감소(대기), V는 증가(신호)라는 방향을 반대로 외우는 실수가 잦다.
- 세마포어만으로는 교착상태를 막지 못한다. P 연산 순서를 잘못 짜면 오히려 대기 상태를 만들 수 있다.
- 스핀락(spinlock)은 대기 중에도 CPU를 점유한 채 조건을 반복 검사해, 프로세스를 잠들게 하는 세마포어와 대기 방식이 다르다.
