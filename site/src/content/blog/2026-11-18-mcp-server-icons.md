MCP 클라이언트에 서버를 여러 개 연결하면 목록이 금세 이름만 빽빽한 텍스트가 된다. 비슷한 이름의 도구가 섞이면 사용자가 승인 창에서 어느 서버의 도구인지 가늠하기도 어렵다. 이를 돕기 위해 최근 스펙 리비전에는 서버와 도구 등에 아이콘을 붙이는 `icons` 필드가 들어갔다. 이 글은 그 필드의 모양과 서버 작성자가 알아 둘 점을 정리한다. 세부 필드는 스펙 리비전에 따라 다를 수 있으니, 적용 전에 사용하는 리비전의 문서를 확인하자.

## 어디에 붙일 수 있나

아이콘은 사람이 보는 UI를 위한 메타데이터다. 모델의 동작에는 영향이 없다. 스펙상 다음 객체들이 `icons` 배열을 가질 수 있다.

- 서버 자신을 설명하는 구현 정보(`serverInfo`)
- 도구(tool)
- 리소스와 리소스 템플릿
- 프롬프트

각 항목은 이미지 하나를 가리키는 객체이고, 배열이므로 해상도나 테마별로 여러 개를 줄 수 있다.

## 모양

도구 정의에 붙인 예시다. 필드 이름은 `src`, `mimeType`, `sizes`, `theme`을 쓰는 것으로 알고 있다.

```json
{
  "name": "search_posts",
  "description": "발행된 글을 키워드로 검색한다",
  "inputSchema": {
    "type": "object",
    "properties": { "query": { "type": "string" } },
    "required": ["query"]
  },
  "icons": [
    {
      "src": "https://example.com/icons/search-48.png",
      "mimeType": "image/png",
      "sizes": ["48x48"],
      "theme": "light"
    },
    {
      "src": "https://example.com/icons/search-dark-48.png",
      "mimeType": "image/png",
      "sizes": ["48x48"],
      "theme": "dark"
    }
  ]
}
```

`src`는 HTTP(S) URL이거나 `data:` URI다. `mimeType`과 `sizes`는 선택 필드라서, 클라이언트가 어떤 파일을 고를지 판단할 힌트로 쓰인다. `theme`는 밝은 배경용인지 어두운 배경용인지를 알려 준다.

## 서버 작성자가 지킬 것

**클라이언트가 안 그릴 수도 있다.** 아이콘은 선택 기능이다. 아이콘이 없어도 도구가 의미를 잃지 않도록 `name`과 `description`을 충실히 쓴다.

**외부 URL은 신뢰 경계를 넘는다.** 클라이언트가 `src`를 내려받으면 그 URL로 요청이 나간다. 그래서 스펙은 클라이언트 쪽에서 출처를 검증하라고 권고하는 것으로 안다. 서버 쪽에서는 아이콘을 자기 도메인에 두는 것이 안전하다. 외부 사용자 입력으로 `src`를 만들지 않는다.

**SVG는 조심한다.** SVG는 스크립트를 품을 수 있어서 클라이언트가 막거나 정제할 수 있다. 호환성을 위해 PNG를 기본으로 두고, SVG는 추가 선택지로 두는 편이 무난하다.

**크기를 아낀다.** `data:` URI로 박으면 `tools/list` 응답이 도구 수만큼 커진다. 작은 아이콘이 아니라면 URL 참조가 낫다.

## 정리

`icons`는 프로토콜의 동작을 바꾸지 않는 표시용 필드다. 그래서 도입 비용이 낮다. 서버 하나에 아이콘 한 벌을 먼저 달고, 도구가 많아질 때 종류별로 나눠 붙이는 순서로 시작하면 된다. 다만 클라이언트마다 지원 범위가 다르므로, 안 보인다고 해서 서버 설정이 틀린 것은 아니다.
