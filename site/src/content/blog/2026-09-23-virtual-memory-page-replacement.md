## 정의

가상메모리(Virtual Memory)는 실제 물리 메모리보다 큰 주소 공간을 프로세스에게 제공하는 기법이다. 프로세스는 실행에 당장 필요한 부분만 물리 메모리에 올려두고, 쓰지 않는 부분은 디스크의 스왑 영역에 남겨둔다. 이 덕분에 물리 메모리 용량을 넘어서는 프로그램도 실행할 수 있고, 여러 프로세스가 제한된 메모리를 동시에 나눠 쓸 수 있다.

## 핵심 원리

가상메모리는 보통 페이징(Paging)으로 구현한다. 프로세스의 주소 공간을 페이지라는 고정 크기 블록으로 나누고, 물리 메모리는 같은 크기의 프레임으로 나눈다. CPU가 참조한 페이지가 물리 메모리에 없으면 페이지 폴트(Page Fault)가 발생하고, 운영체제는 디스크에서 그 페이지를 읽어와 빈 프레임에 적재한다.

문제는 빈 프레임이 없을 때다. 이미 올라와 있는 페이지 중 하나를 내보내야 하는데, 어떤 페이지를 고를지 정하는 규칙이 페이지 교체 알고리즘이다.

## 예시 — 네 가지 교체 알고리즘

**FIFO(First-In First-Out)**: 가장 먼저 올라온 페이지부터 내보낸다. 구현은 단순하지만 오래 전에 올라왔어도 자주 쓰이는 페이지까지 내보낼 수 있다. 프레임 수를 늘렸는데 오히려 페이지 폴트가 늘어나는 Belady's Anomaly가 FIFO에서 나타날 수 있다는 점이 특징이다.

**LRU(Least Recently Used)**: 가장 오랫동안 참조되지 않은 페이지를 내보낸다. 최근에 쓰인 페이지는 곧 다시 쓰일 가능성이 높다는 지역성(locality) 원리에 기대므로 실제 성능이 좋은 편이지만, 참조 시각을 계속 추적해야 해서 구현 비용이 크다.

**LFU(Least Frequently Used)**: 참조 횟수가 가장 적은 페이지를 내보낸다. 초반에 잠깐 많이 쓰이다가 이후로는 전혀 쓰이지 않는 페이지를 계속 남겨두는 약점이 있다.

**OPT(Optimal, 최적 교체)**: 앞으로 가장 오랫동안 사용되지 않을 페이지를 내보낸다. 이론상 페이지 폴트가 가장 적지만 미래의 참조 순서를 미리 알아야 하므로 실제 시스템에는 구현할 수 없고, 다른 알고리즘의 성능을 비교하는 기준선으로만 쓰인다.

같은 참조열을 FIFO와 LRU에 각각 대입해 프레임 상태를 한 칸씩 채워보면 두 알고리즘이 어느 지점에서 다른 페이지를 내보내는지, 그래서 총 폴트 횟수가 왜 달라지는지 눈으로 확인할 수 있다.

## 스래싱과 워킹셋

프레임 수가 부족한 상태에서 여러 프로세스가 페이지 교체를 반복하느라 CPU 사용률은 오히려 낮아지고 디스크 입출력만 늘어나는 현상을 스래싱(Thrashing)이라 한다. 이를 완화하는 접근이 워킹셋(Working Set) 모델로, 프로세스가 일정 시간 동안 실제로 참조한 페이지 집합만큼만 프레임을 배정해 최소한의 지역성을 보장한다.

## 시험에 자주 나오는 포인트

FIFO의 Belady's Anomaly는 단골 함정이다. "프레임을 늘렸는데 폴트가 늘었다"는 조건이 나오면 FIFO를 의심한다. LRU와 LFU는 "최근이냐 횟수냐"로 구분하고, OPT는 실제 시스템에 쓸 수 없는 이론적 기준이라는 점을 기억한다. FIFO·LRU·OPT는 주어진 참조열로 페이지 폴트 횟수를 직접 계산하는 문제로도 자주 나오므로, 프레임 상태를 표로 그려가며 손으로 계산하는 연습이 필요하다.
