## 정의

디스크 스케줄링은 여러 입출력 요청이 대기할 때 **어떤 순서로 처리할지** 정해 헤드의 총 이동 거리를 줄이는 기법이다. 하드디스크의 접근 시간은 탐색 시간(seek time, 헤드를 해당 트랙으로 옮기는 시간), 회전 지연(rotational latency), 전송 시간으로 이루어지는데, 이 중 탐색 시간이 가장 크다. 그래서 스케줄링의 목표는 사실상 탐색 거리를 줄이는 것이다.

## 알고리즘별 원리

| 알고리즘 | 처리 방식 | 특징 |
|---|---|---|
| FCFS | 도착 순서대로 | 공정하지만 이동 거리가 큼 |
| SSTF | 현재 헤드에서 가장 가까운 트랙 먼저 | 평균 성능 좋음, 먼 요청은 기아(starvation) 가능 |
| SCAN | 한 방향으로 끝까지 이동하며 처리, 끝에서 반대로 | 엘리베이터 방식, 기아 완화 |
| C-SCAN | 한 방향으로만 처리, 끝에 닿으면 반대편 끝으로 되돌아가 다시 시작 | 대기 시간 편차가 작음 |
| LOOK | SCAN과 같되 요청이 있는 마지막 트랙에서 방향 전환 | 끝까지 가지 않아 낭비 감소 |
| C-LOOK | C-SCAN과 같되 요청 범위 안에서만 이동 | 낭비 최소화 |

## 예제로 계산하기

트랙 범위를 0~199, 현재 헤드 위치를 53, 대기 큐를 다음과 같다고 하자.

```text
98, 183, 37, 122, 14, 124, 65, 67
```

**FCFS**: 53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67

```text
45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = 640
```

**SSTF**: 가까운 순으로 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183

```text
12 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = 236
```

**LOOK** (처음 방향이 낮은 번호 쪽): 53 → 37 → 14 → 65 → 67 → 98 → 122 → 124 → 183

```text
16 + 23 + 51 + 2 + 31 + 24 + 2 + 59 = 208
```

같은 요청인데 FCFS는 640, SSTF는 236, LOOK은 208이다. SCAN은 LOOK과 순서가 같지만 14에서 트랙 0까지 더 내려갔다가 돌아오므로 14만큼 내려가는 구간이 추가되어 LOOK보다 길다(이 예제에서는 236).

## 시험 포인트

- **SSTF의 약점은 기아 현상**이다. 헤드 근처에 요청이 계속 들어오면 먼 트랙의 요청이 무한정 밀릴 수 있다.
- **SCAN은 엘리베이터 알고리즘**이라 불린다. 양 끝 트랙에 가까운 요청이 중간 요청보다 평균 대기가 길어질 수 있고, C-SCAN은 이를 균등하게 만들려는 변형이다.
- **SCAN/C-SCAN은 끝 트랙까지 이동**하고, **LOOK/C-LOOK은 마지막 요청 위치까지만** 이동한다는 차이를 구분한다. 계산 문제에서는 문제에 "끝까지 이동"이 명시됐는지, 되돌아가는 구간을 이동 거리에 포함하는지 조건을 먼저 확인한다.
- 이동 거리 계산은 인접한 두 위치의 차(절댓값)를 순서대로 더하면 된다. 헤드의 현재 위치와 진행 방향이 주어지는지 반드시 확인한다.
- 스케줄링은 탐색 시간을 줄이는 기법이므로, 탐색 시간이 없는 SSD에서는 효과가 크게 다르다는 점도 알아 두면 좋다.
