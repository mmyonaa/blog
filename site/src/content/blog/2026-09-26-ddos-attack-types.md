## DoS와 DDoS

DoS(Denial of Service)는 시스템이나 서비스가 정상 요청을 처리하지 못하도록 자원을 고갈시키는 공격이다. 공격자가 단일 지점에서 트래픽을 보내면 DoS, 여러 대의 좀비 PC(봇넷)를 동원해 분산된 지점에서 동시에 공격하면 DDoS(Distributed DoS)라 부른다. DDoS는 출발지 IP가 분산되어 있어 단순 차단으로는 막기 어렵고, 봇넷 규모에 따라 공격 트래픽 양 자체가 방어 인프라의 대역폭을 넘어설 수 있다.

DoS/DDoS 공격은 어느 계층의 자원을 노리느냐로 크게 나뉜다. 전송 계층에서 연결 상태 테이블을 채우는 공격, 네트워크 계층에서 트래픽량 자체로 밀어붙이는 증폭 공격, 응용 계층에서 서버 프로세스나 연결 슬롯을 오래 점유하는 공격이 대표적이다.

## SYN 플러딩 — 전송 계층

TCP는 연결을 맺을 때 3-way handshake를 거친다.

```text
Client -> Server : SYN
Server -> Client : SYN+ACK
Client -> Server : ACK
```

서버는 SYN을 받으면 ACK를 기다리는 반열림(half-open) 연결을 백로그 큐에 저장한다. 공격자는 출발지 IP를 위조한 SYN을 대량으로 보내고 마지막 ACK를 보내지 않는다. 서버는 존재하지 않는 상대의 ACK를 계속 기다리며 백로그 큐가 가득 차고, 이후 들어오는 정상 연결 요청은 큐에 자리가 없어 거부된다.

방어로는 SYN Cookie가 대표적이다. 서버가 백로그에 연결 정보를 바로 저장하지 않고, 연결 상태를 암호학적으로 인코딩한 값을 SYN+ACK의 시퀀스 번호에 실어 보낸 뒤, 정상적인 ACK가 돌아올 때만 그 값을 검증해 연결을 복원한다. 이 방식은 위조된 SYN에 대해 서버 자원을 미리 소모하지 않는다는 장점이 있다.

## Smurf 공격 — 네트워크 계층 증폭

Smurf는 ICMP Echo Request(핑)를 이용한 증폭 공격이다. 공격자는 출발지 IP를 피해자 IP로 위조한 ICMP Echo Request를 네트워크의 브로드캐스트 주소로 보낸다. 브로드캐스트 대역에 있는 모든 호스트가 이 요청을 받아 동시에 피해자에게 Echo Reply를 보내면서, 공격자가 보낸 트래픽 하나가 네트워크 내 호스트 수만큼 증폭되어 피해자에게 쏟아진다.

방어는 라우터에서 외부로 나가는 IP 브로드캐스트 주소로의 패킷 전달을 차단하는 것이다. 또한 출발지 IP 위조를 막는 ingress filtering(BCP38에서 권고하는, 자신의 네트워크 대역이 아닌 출발지 IP를 가진 패킷을 경계에서 걸러내는 방식)을 적용하면 위조된 출발지 자체가 통과하지 못한다.

## Slowloris — 응용 계층

Slowloris는 대역폭이 아니라 서버의 동시 연결 슬롯을 노린다. 공격자는 HTTP 요청 헤더를 끝까지 완성하지 않고 일부만 보낸 뒤, 연결이 끊기지 않을 정도의 간격으로 나머지 헤더 조각을 아주 느리게 이어 보낸다. 서버는 요청이 끝나기를 기다리며 해당 연결을 계속 열어 두는데, 이런 연결을 소수의 자원만으로 대량 생성하면 서버의 최대 동시 연결 수가 모두 소진되어 정상 사용자가 접속하지 못한다.

방어로는 연결당 헤더 수신 제한 시간을 짧게 설정하거나, 요청 완성 속도가 비정상적으로 느린 연결을 끊는 리버스 프록시·WAF를 앞단에 두는 방법이 쓰인다.

## 시험에 자주 나오는 포인트

- DoS는 단일 출발지, DDoS는 봇넷을 통한 분산 출발지라는 차이를 구분한다.
- 공격이 노리는 계층으로 분류하는 문제가 자주 나온다. SYN 플러딩은 전송 계층(TCP 연결 상태), Smurf는 네트워크 계층(ICMP 증폭), Slowloris는 응용 계층(HTTP 연결 유지)이다.
- Smurf처럼 적은 트래픽을 큰 트래픽으로 부풀리는 방식을 증폭(amplification) 공격이라 하며, 이때 증폭에 이용되는 제3의 네트워크를 반사체(reflector)라 부른다.
- SYN Cookie는 백로그 큐를 채우지 않고 연결 상태를 시퀀스 번호에 인코딩해 검증한다는 점이 핵심이다.
