배열에서 조건을 만족하는 쌍이나 구간을 찾을 때 가장 먼저 떠오르는 방법은 이중 반복문이다. 원소가 n개면 O(n^2)이라 n이 10만만 되어도 시간 제한에 걸린다. 투 포인터(two pointers)는 인덱스 두 개를 조건에 따라 한 방향으로만 움직여 같은 문제를 O(n)에 푸는 기법이다.

## 핵심 아이디어

포인터를 옮길 때마다 "이 후보들은 더 볼 필요가 없다"는 근거가 있어야 한다. 그 근거는 보통 정렬이나 원소의 부호(모두 0 이상)에서 나온다. 포인터가 앞으로만 가고 되돌아오지 않으므로 각 포인터는 최대 n번 움직이고, 전체는 O(n)이다.

대표 유형은 두 가지다.

| 유형 | 포인터 시작 | 이동 방식 |
| --- | --- | --- |
| 양끝에서 좁히기 | 왼쪽 끝, 오른쪽 끝 | 서로 마주 보며 이동 |
| 같은 방향(슬라이딩 윈도우) | 둘 다 왼쪽 | 오른쪽이 확장, 왼쪽이 수축 |

## 유형 1: 정렬된 배열에서 합이 target인 쌍

오름차순 배열에서 합이 target인 두 원소를 찾는다. 양끝에 포인터를 두고 합을 본다.

- 합이 target보다 작으면 왼쪽 포인터를 오른쪽으로 옮긴다. 더 큰 값이 필요하기 때문이다.
- 합이 크면 오른쪽 포인터를 왼쪽으로 옮긴다.

```python
def pair_sum(a, target):
    """오름차순 정렬된 a에서 합이 target인 (i, j) 인덱스를 반환. 없으면 None."""
    l, r = 0, len(a) - 1
    while l < r:
        s = a[l] + a[r]
        if s == target:
            return l, r
        if s < target:
            l += 1
        else:
            r -= 1
    return None

print(pair_sum([1, 3, 4, 6, 9, 12], 10))  # (2, 3)
print(pair_sum([1, 3, 4, 6, 9, 12], 100))  # None
```

왜 옳을까? 합이 target보다 작을 때 a[l]은 현재 a[r]과 짝지어도 부족하다. a[r]보다 작은 다른 값과는 더 부족하므로, a[l]은 어떤 짝으로도 답이 될 수 없어 안전하게 버릴 수 있다. 정렬되어 있다는 사실이 이 논리를 지탱한다. 정렬되지 않은 배열이라면 먼저 정렬하는 O(n log n)이 들어가며, 원래 인덱스가 필요하면 정렬 전 위치를 따로 저장해야 한다.

## 유형 2: 합이 k 이하인 가장 긴 연속 구간

원소가 모두 0 이상인 배열에서, 합이 k 이하인 연속 부분 배열의 최대 길이를 구한다. 오른쪽 포인터로 구간을 늘리고, 합이 k를 넘으면 왼쪽 포인터로 줄인다.

```python
def longest_at_most(a, k):
    """원소가 모두 0 이상일 때, 합이 k 이하인 연속 구간의 최대 길이."""
    best = 0
    total = 0
    l = 0
    for r in range(len(a)):
        total += a[r]
        while total > k:
            total -= a[l]
            l += 1
        best = max(best, r - l + 1)
    return best

print(longest_at_most([2, 1, 3, 1, 1, 4], 5))  # 3  ([1, 3, 1] 또는 [3, 1, 1])
```

안쪽에 while이 있어 이중 반복문처럼 보이지만, l은 한 번 증가하면 줄지 않고 최대 n까지만 간다. 따라서 전체 연산은 2n 정도로 O(n)이다.

이 유형은 음수가 섞이면 성립하지 않는다. 구간을 줄이면 합이 반드시 감소한다는 단조성이 깨지기 때문이다. 음수가 있다면 누적합과 해시 맵 같은 다른 방법을 써야 한다.

## 적용 전 점검

- 포인터를 옮길 때 버려지는 후보가 정답이 아닌 이유를 한 문장으로 설명할 수 있는가
- 정렬되어 있거나 값의 단조성이 있는가
- 종료 조건(`l < r` 인지 `l <= r` 인지)이 문제의 의미와 맞는가. 같은 원소를 두 번 쓰면 안 되는 문제는 `l < r`이다

투 포인터는 "단조성이 있으면 되돌아갈 필요가 없다"는 한 가지 관찰에 기대는 기법이다. 이중 반복문이 떠오를 때 조건이 이 관찰에 맞는지부터 확인하면 풀이가 크게 단순해진다.
