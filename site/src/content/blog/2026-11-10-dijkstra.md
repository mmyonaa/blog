## BFS로는 왜 부족한가

BFS는 간선 개수가 가장 적은 경로를 찾는다. 모든 간선의 비용이 같을 때만 그 경로가 곧 최단 경로다. 도로 길이나 통신 지연처럼 간선마다 가중치가 다르면 "거치는 정점이 적은 길"이 "가장 짧은 길"이 아닐 수 있다. 이때 쓰는 것이 Dijkstra 알고리즘이다. 시작 정점에서 다른 모든 정점까지의 최단 거리를 한 번에 구한다.

## 핵심 아이디어

Dijkstra는 아직 확정되지 않은 정점 중 현재 거리가 가장 작은 정점을 하나 골라 확정하는 일을 반복한다.

```text
1. dist[시작] = 0, 나머지는 무한대
2. 미확정 정점 중 dist가 가장 작은 u를 꺼낸다 (이제 u의 거리는 확정)
3. u에서 나가는 간선 (u, v, w)마다
   dist[u] + w < dist[v] 이면 dist[v]를 갱신한다 (완화, relaxation)
4. 미확정 정점이 없을 때까지 2~3을 반복
```

가장 작은 거리의 정점을 확정해도 되는 이유는, 간선 가중치가 0 이상이면 다른 우회로를 거쳐 더 짧아질 수 없기 때문이다. 우회하면 이미 더 큰 거리를 지나야 하고, 거기에 음이 아닌 값을 더할 뿐이다.

## 구현: 힙으로 가장 가까운 정점 꺼내기

"가장 작은 dist를 가진 정점"을 매번 선형 탐색하면 느리다. 최소 힙(우선순위 큐)을 쓰면 꺼내는 비용이 log 수준이다. Python의 `heapq`는 감소 키(decrease-key) 연산이 없어서, 거리가 갱신될 때마다 새 항목을 넣고 꺼낼 때 낡은 항목을 건너뛰는 방식을 흔히 쓴다.

```python
import heapq

def dijkstra(graph, start):
    dist = {node: float("inf") for node in graph}
    dist[start] = 0
    heap = [(0, start)]  # (거리, 정점)

    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:      # 이미 더 짧은 거리로 처리된 낡은 항목
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist

graph = {
    "A": [("B", 4), ("C", 1)],
    "B": [("D", 1)],
    "C": [("B", 2), ("D", 7)],
    "D": [],
}
print(dijkstra(graph, "A"))  # {'A': 0, 'B': 3, 'C': 1, 'D': 4}
```

A에서 B로 직접 가면 4지만 C를 거쳐 가면 1 + 2 = 3이다. 간선 수만 보면 직접 가는 쪽이 짧아 보이는데, 가중치를 반영해야 올바른 답이 나온다. D까지는 A, C, B, D 순으로 1 + 2 + 1 = 4가 최단이다.

## 복잡도

정점 수를 V, 간선 수를 E라고 하면 이 힙 구현은 O((V + E) log V)다. 각 간선이 힙에 최대 한 번씩 항목을 추가하므로 힙 크기는 E 이하이고, 삽입과 삭제가 log 비용이다. 간선이 매우 많은 조밀한 그래프에서는 힙 없이 배열을 선형 탐색하는 O(V²) 구현이 더 단순하고 비슷하게 빠를 수도 있다.

## 주의할 점

- **음수 간선은 안 된다.** 확정한 정점의 거리가 나중에 더 줄어들 수 있어 정당성이 깨진다. 음수 간선이 있으면 Bellman-Ford 같은 다른 알고리즘을 쓴다.
- **낡은 항목 건너뛰기를 빼먹지 말 것.** `if d > dist[u]: continue`가 없으면 결과는 맞더라도 같은 정점을 여러 번 처리해 불필요하게 느려진다.
- **경로 자체가 필요하면** 갱신할 때 `prev[v] = u`를 함께 기록하고, 도착점에서 거슬러 올라가 복원한다.
- **모든 간선 가중치가 같다면** BFS로 충분하다. Dijkstra는 가중치가 있을 때 BFS를 일반화한 것으로 볼 수 있다.

코딩테스트에서는 "최소 비용", "최단 시간"이라는 표현과 함께 가중치 그래프가 나오면 먼저 Dijkstra를 떠올리면 된다. 간선 가중치의 부호가 음수가 아닌지만 확인하면 된다.
